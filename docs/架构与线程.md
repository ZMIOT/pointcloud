# 模块与线程约定

Launcher 创建 QApplication、设置 VTK 所需 OpenGL 格式，再启动 FrameworkCore。FrameworkCore 加载 UI 与算法插件，MainUI 通过 Host 服务获取参数工厂和可视化工厂。算法插件只引用 FrameworkSDK、QtCore 及计算依赖。

SDK DLL 提供 QObject 信号载体、参数解析/校验及快照工具。界面类只在 `UiInterfaces.h` 出现；算法包含 `Algorithm.h`，不依赖 QtWidgets。

## 运行状态

一次运行按 `Idle → Running ↔ Paused → Finished/Cancelled/Failed → Idle` 转换。参数在开始时复制。算法实例的创建、validate、execute、销毁均位于同一个工作线程。最终信号在主线程发布，发布前工作线程完成退出。

检查点流程：

1. 工作线程在互斥锁下分配序号并登记等待状态。
2. 在工作线程复制/采样数据，排队发送主线程事件。
3. 主线程检查历史预算、回收旧窗口、创建新窗口并提交显示。
4. 主线程确认该序号已展示。继续模式也等待此确认，避免无限排队产生快照。
5. 单步模式继续等待针对当前序号的下一步许可；继续或停止可以唤醒等待。

条件变量使用谓词，许可即使早于等待到达也不会丢失。“下一步”不会累积为多个未来步骤的许可。恢复单步从下一个尚未放行的检查点开始生效。停止不要求窗口确认，防止关闭期间死锁。

主窗口关闭时如果算法仍在运行，先请求取消并保持事件循环，直到计算返回后再关闭。Launcher 退出时再次停止并 join 工作线程，销毁窗口和数据，然后释放运行时对象。插件加载器设置 PreventUnloadHint，进程中不执行 DLL 热卸载。

## 内存与历史

默认保留最近 8 个 frame，并同时限制 512 MiB 快照缓冲区。关闭窗口不会删除保留中的快照；再次打开同一步骤复用已有窗口。新运行会清空上次快照并标记历史条目已释放。

每次 checkpoint 都复制点云字节和图像内容。超过单帧预算时，点云按原有索引均匀抽样，图像缩放；几何辅助图元整体省略。窗口明确标识采样。算法输入和最终输出不受这些显示操作影响。

预算统计包括点云、图像和几何数组，不包括 Qt/VTK 元数据、显示转换点云、GPU 缓冲区或算法计算内存。保留窗口越多，真实进程内存可能显著大于快照预算。

## 构建契约

插件元数据包含 SDK 版本、稳定 ID、算法/参数版本和构建标识。构建标识记录编译器版本、指针宽度、Qt/PCL/VTK/OpenCV 版本、C++ 标准、CRT 模式和 Debug/Release。Qt 加载器再校验自身插件格式。

公共接口为同工具链 C++ 接口，不是跨语言/跨编译器稳定 C ABI。开发者需遵守一致的 Eigen 对齐、迭代器调试、结构体打包和指令集选项；元数据不能侦测所有人为覆盖的编译选项。
