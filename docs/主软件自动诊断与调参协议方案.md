# 主软件自动诊断与调参协议方案

状态：方案草案，v1 基础能力已部分实现。具体字段见[自动诊断协议](自动诊断协议.md)，已完成和未完成范围见[实施计划](自动诊断实施计划.md)。数值建议的验收阈值仍须通过标注工件确定。

## 目标

交付后的使用者应能知道：结果在哪个阶段先出现问题、这个问题能否通过现有参数改善、推荐试什么设置、试跑后的改善与退化分别在哪里，以及建议有多少证据支持。主软件统一提供自动检查、试跑、比较、报警和界面；算法模块提供主软件无法自行推断的几何诊断事实和参数作用描述。

本方案面向完整点云及其多个输出，不预设一次运行只寻找一个特征点。既要处理整个输入不可用，也要处理“多数区域正确、少数区域漏检或错选”。目前工程中的 CAR 有实测边缘和拟合轨迹两个结果，[ExtractFeature2](../algorithms/extract_feature2/README.md) 与[帧焊缝算法](../algorithms/frame_seam/README.md)分别有左右轨迹；未来还可能接入离散特征点、曲线、面、区域或测量值。主软件不能用同一种点数指标评价这些不同输出。

推荐值不得只由算法自身的候选分数、输出点数或连续段数决定。没有人工确认的参考边缘时，软件可以评价内部一致性，不能宣称绝对定位正确。

## 当前工程基础与缺口

- [算法插件接口](../sdk/include/fw/Algorithm.h) 提供参数定义、输入校验和执行；[结果结构](../sdk/include/fw/Data.h) 已有 `metrics` 和调试快照，但没有统一的诊断代码、区域和参数作用契约。
- [主软件运行时](../core/Runtime.cpp) 一次执行一个算法，完成后发出结果；[主界面](../plugins/main/MainUI.cpp) 将普通结果加入数据列表，并把统计写入日志。目前没有区分正式运行与临时试参运行的通道。
- CAR 算法已有六个调试阶段、候选拒绝原因及其汇总统计，见 [插件适配](../algorithms/carExtractFeature/MyAlgorithm.cpp) 和 [核心数据类型](../algorithms/carExtractFeature/core/LapEdge.h)。这些数据能作为首个接入样例，但缺少面向普通用户的逐区域诊断和建议。
- 当前 `IAlgorithm::validate()` 返回文本。主软件可先依据声明式输入要求做结构化检查；算法专有校验若仅返回文本，应显示原错误并停止数值推荐，不应解析文字猜测错误类别。

## 职责边界

| 主软件 | 算法库或其诊断档案 |
| --- | --- |
| 校验协议、调度运行与试跑、限制资源、允许取消 | 声明输入条件、输出语义、参数作用及合法范围 |
| 根据结构化问题定位阶段和区域，显示报警 | 上报稳定问题代码、观测值、门槛和证据 |
| 按规则挑选少量变体，顺序试跑并比较 | 在相同输入与参数下给出可复现结果；不依赖界面状态 |
| 结合标注、几何约束和退化检查给出建议等级 | 提供必要的原始索引或几何位置供跨试跑对齐 |
| 维护版本化规则库、工件样本、试跑记录和界面 | 不在算法计算代码里实现通用试参流程或界面 |

主软件中的规则库按算法 ID 与版本加载诊断档案。档案可以随算法交付，但由主软件校验并执行；新算法无需修改主软件的试跑调度代码。没有档案或协议不兼容的旧算法继续正常运行，只是不提供专有数值建议。

## 拟定协议

协议版本独立于算法版本和参数版本。第一版采用可选的声明式数据，避免直接给现有插件接口增加虚函数而破坏已编译插件兼容性：参数定义增加有版本的诊断档案，运行结果的 `metrics` 增加有版本、受大小限制的诊断摘要。实现时应为这两部分编写机器可校验的模式定义。逐点明细或大量区域数据不宜无限放入 JSON；确有需要时再设计独立的可选扩展接口。

### 算法声明

每个接入算法应声明：

1. 算法及诊断协议版本、输入字段和顺序等前提、输出角色、几何类型、坐标系与单位约定。输出角色可区分原始实测、拟合轨迹、分割区域和测量结果；还要声明一个工件可能有几个同类目标、是否允许分段或缺口。
2. 每个可试参数的稳定 ID、影响阶段、合法范围、试探步长、预期可观察变化、可能退化，以及不能解决的问题。
3. 每个诊断代码的稳定含义、所属阶段、严重程度、所需证据字段和可关联的参数。代码用于机器判断；中文说明仅用于展示。
4. 结果对齐方式，例如原始点索引、物理几何位置和特征或轨迹身份。CAR 的 `section_id` 是本次运行恢复的几何截面编号，不能单独当作跨输入稳定标识或采集时间戳；多个目标也不能只按输出数组顺序配对。
5. 适用的输入区域、可观测性判定及分母口径。未扫描、被遮挡、不属于目标范围的区域，与有足够数据却未识别出的区域必须区分。

### 运行诊断报告

每条问题至少包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `code`、`stage` | 稳定问题代码与发生阶段；不得通过解析人类可读消息推断 |
| `severity` | 信息、警告或严重问题；与算法运行的成功/失败状态分开 |
| `region` | 可是点、截面范围、包围盒、多边形、曲线段或整份输入；包含可对齐的几何位置或原始索引 |
| `observed`、`limit`、`unit` | 可复核的测量值、判定门槛及单位；不适用时明确省略 |
| `support` | 支持点数、邻截面数或其他证据量；需说明其统计口径 |
| `scope`、`visibility` | 所属目标与有效区域；区分可观测、缺测、目标不适用和无法判定 |
| `origin` | 异常来源状态；未经独立证据，不能把真实产品瑕疵、采集噪声和算法错误互相替代 |
| `summary` | 供界面展示的简明解释，不参与规则匹配 |

报告还应包含输入身份、算法版本、参数快照和输出角色，使试跑结果只能与同一输入及兼容版本比较。大规模点云只上报聚合统计、问题区段和有限数量的代表位置。所有数字须为有限值，区域必须落在输入或输出的有效范围内。

### 整片点云与多结果诊断

主软件应建立三级视图，而不是用一个整体通过率概括结果：

1. **整云级：**输入字段、单位、坐标方向、采样密度与噪声分布、可处理区域、运行状态和资源消耗。全局前提失败可终止诊断；局部密度变化不能直接判为整云失败。
2. **区域或目标级：**按空间块、扫描截面区段、工件部位或输出目标聚合。分别记录可观测范围、覆盖范围、漏检和误检候选、连续段长度、断裂与错误连接、左右或多目标是否混淆。把连续相邻的问题合并成一个区域事件，并保留严重程度、范围和代表位置，避免逐点报警淹没使用者。
3. **局部证据级：**针对被标记区域查看具体点、候选、曲面残差或其他判据。只为用户选中的问题区准备详细点云视图；普通运行不复制整份点云作为诊断快照。

输出比较按声明的几何类型选择方法：离散点可用空间邻近及身份约束配对；曲线或轨迹需同时比较位置、覆盖区段、分段和连接拓扑；区域或面需比较边界、覆盖与相互重叠。多个结果先按语义角色和几何身份匹配，再比较位置，不能按数组下标或总点数判断改善。插补点与原始实测点应分别统计；质量分数若未校准，不当作正确概率。

“没有输出”也需结合可观测性解释：输入区域缺测、物理特征本来不存在、算法证据不足和算法漏检是不同状态。没有参考标注或可观测区域定义时，主软件不能把所有空白区域计算为漏检。整云覆盖率必须给出分母的来源与适用范围。

工业工件可能带有真实局部瑕疵或连续瑕疵。异常条目须保留“来源未判定/疑似物理缺陷”等状态；仅凭平滑后异常消失，不能判为算法改善。疑似真实缺陷默认进入人工复核，不由自动调参抹平。

## 主软件推荐流程

1. **输入体检。** 检查文件字段、点数、非有限值、声明的点序与方向等前提。输入条件不满足时给数据修正建议，不试无关数值参数。
2. **定位最早失效阶段。** 分析各阶段通过率、问题区段及观测值到门槛的差距。区分可调参数、缺少必要数据和算法判据失配。
3. **生成受限试验。** 只对诊断档案允许的参数试少量相邻值；一次改变一个参数，记录基线和变体。试跑按现有单任务能力顺序执行，并限制次数、耗时和内存，支持取消。
4. **独立比较。** 优先使用人工确认的参考点、线段或区域，检查错层、漏检、关键位置偏差和错误连接；同时检查新增/丢失区域、最大偏移、分段变化及原本正确区域的退化。对多条轨迹先匹配身份，再比较对应区域。不得只优化算法自己生成的质量分数。
5. **检查全局副作用。** 一组参数可能修复局部却破坏另一侧或另一个工件部位。试参报告必须同时展示目标区域的改善和整云其他区域的退化；若没有共同合格的全局设置，不强推一个数值，应考虑区域自适应算法或针对数据条件修正规则。
6. **给出分级建议。** 优先推荐一段通过验收的稳定区间，再给便于操作的数值。若试验结论冲突、工件明显超出验证范围或没有可调整参数，停止给数值建议并说明需要复核的位置。

试跑结果只暂存于对比会话，不加入正式数据列表，不覆盖用户当前参数或正式输出。使用者采用建议后才更新参数；应能一键恢复原值，并保留试跑参数及诊断依据。主软件需为试跑与正式运行建立明确的内部标记，避免当前普通 `finished` 处理直接将每次试跑输出加入数据列表。

## 界面与报警

普通用户的入口为“自动检查”。主界面先在完整点云上显示按严重程度聚合的问题区域，再提供按目标或区域筛选的问题清单。选中一个问题后显示阶段、建议的调整方向与数值、依据、预计改善和其他区域可能退化，并提供前后点云叠加对比、采用建议和恢复原值。高级详情显示原始观测值、门槛、拒绝原因和试跑记录。局部警告可以与成功输出共存，不应全部显示成算法失败；不能把成千上万个失败点逐条弹窗。

建议标明证据等级：

- **已验证：**同类工件的标注样本与当前试跑共同支持。
- **待人工确认：**当前试跑的内部几何证据改善，但没有足够参考真值。
- **不给数值建议：**输入无效、缺少支持数据、试验互相矛盾或超出已验证范围。

CAR 的示例映射：扫描截面恢复失败优先检查输入点序或方向；单截面无候选检查台阶与噪声，不能通过轨迹平滑补救；邻截面本身缺点时调邻域倍率无法产生证据；实测点正确而轨迹抖动时才试平滑强度；错误跨缺口连接时检查插补证据及最大补点数。具体数值须经试跑和样本验证，不固定写在错误代码里。

## 标注、校准与验收

样本库按工件类型、扫描方式和算法版本管理，覆盖不同密度、旋转或反向扫描、波纹转折、毛刺、短缺口、长缺口和缺测。对整云不要求逐点手工标注：可先标注关键点、正确线段与端点、禁止连接的位置、目标存在或不存在的区域，以及缺测或不可判定的区域。多目标工件还应标明左右或目标身份。标注应保留坐标系、单位和来源。用一部分样本校准规则及稳定参数区间，另留未参与调参的工件做验收。

验收不仅检查推荐后的平均表现，还检查最差关键区域、错层、漏检、错误连接、左右或多目标混淆、建议导致的其他区域退化，以及面对不可调故障时能否拒绝给数字。分别报告整云、各目标和问题区段的结果；大范围正确不能掩盖一小段关键边缘的严重错误。允许的误差、覆盖率和运行预算由交付需求与参考标注确定，不在没有业务依据时预设。旧插件兼容、取消、重复运行一致性、试跑结果隔离和版本不匹配处理也必须纳入自动测试。

## 文档与 AI 开发流程

实施时交付四件相互对应的材料：

1. **规范文档：**协议字段、版本、兼容、单位、严重程度和报警语义。
2. **算法接入指南及模板：**如何声明参数作用、上报诊断、输出可对齐结果；包含一个完整可运行示例。
3. **主软件实现说明：**规则档案、试跑调度、比较、证据评级、界面和恢复机制。
4. **机器校验及一致性测试：**覆盖缺字段、非法数值、未知代码、版本冲突、取消和输出隔离。

在项目开发规则、[现有算法开发文档](算法开发.md) 和算法模板中明确：AI 开始编写或修改算法前应先阅读协议及接入指南。文档要求必须由模式校验和一致性测试支撑，不能只依赖提示词。

## 分阶段实施

| 阶段 | 主要交付 | 通过条件 |
| --- | --- | --- |
| 1. 协议定版 | 规范、模式定义、CAR 示例、兼容策略 | 主软件能校验报告并正确处理旧插件与未知诊断 |
| 2. 诊断基础 | 逐区域事实、问题代码、阶段定位界面 | 能说明问题先出现在哪一步及依据 |
| 3. 试跑对比 | 有界顺序试跑、临时结果、对比、取消、恢复 | 不污染正式输出；同输入可复现 |
| 4. 建议引擎 | 规则档案、证据等级、具体方向或数值 | 可调问题给合理方向；不可调问题不乱推荐 |
| 5. 工件验收 | 标注样本、稳定区间、留出工件回归 | 建议改善真实错误且不造成不可接受的局部退化 |

此顺序将“诊断正确”和“参数建议正确”分开验收，避免界面先给出看似具体、实际没有证据的数值。
