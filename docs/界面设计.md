# 界面布局与样式

本次依据 Qt 官方 [qt-ui-design skill](https://github.com/TheQtCompanyRnD/agent-skills/blob/71d6c10da78b9a764468ae11c86ab3bc4ca4921f/skills/qt-ui-design/SKILL.md) 的信息层级、渐进展示、语义颜色、字体、焦点与可访问性原则进行优化。引用版本固定为 `71d6c10da78b9a764468ae11c86ab3bc4ca4921f`。该 skill 是面向 Qt 6 的概念设计指南，本工程将适用原则落实到现有 Qt 5 Widgets / Fusion / QSS，没有引入 QML 或改变 SDK 接口。

## 设计上下文

- Windows x64 桌面、矩形窗口、简体中文、鼠标与键盘，按桌面约 60 cm 阅读距离设计。
- 默认深色工作区；“视图 → 深色主题”可切换亮色并保存主题偏好，三维视图保持深色背景。
- 启动尺寸按屏幕可用**逻辑像素**计算并预留窗口边框空间；最小尺寸上限为 860×520，屏幕更小时进一步缩小。Qt 5.14 及以上使用 PassThrough 保留 Windows 的 125%/150% 等实际比例，不取整至 200%。
- 短窗口默认收起执行记录，可从“视图”菜单打开；高度不足 600 逻辑像素时收起重复标题和输入说明，保留数据列表、图层和运行操作。
- 主要内容是点云和运行操作；其次是输入、参数和结果；调试、预设和资源设置逐步展开。

## 审查与修改

| 级别 | 问题 | 落实方式 |
| --- | --- | --- |
| Warning | 顶部操作拥挤，运行与参数距离较远 | 文件操作留在顶部，算法选择移到右侧，运行/停止固定在参数底部 |
| Warning | 执行记录占用主要视图空间 | 左侧数据、中央点云、右侧参数；执行记录仅占中央底部，支持拖动与隐藏 |
| Warning | 参数排列不齐，纵向占用过大 | 设计稿适配后，名称位于控件上方；长名称自动换行，单位附在名称后，范围的下限/上限并排，说明仍可悬停查看 |
| Warning | 字体较小，默认字体回退不一致 | 当前正文至少 10.5 pt，支持字体倍率；Windows 优先已安装的 Microsoft YaHei UI，其他平台保留系统字体 |
| Warning | 样式验证时深色复选框边界与数字箭头不清晰 | 统一语义边界颜色；内嵌两套 SVG 箭头与勾选标记 |
| Warning | 放大字体后参数数值被遮挡 | 参数区域滚动，运行按钮固定在面板底部；放大字体烟测检查按钮仍位于窗口内 |
| Opportunity | 新用户没有操作指引 | 空白画布增加导入入口和简短流程说明 |
| Opportunity | 高级操作持续占据工具栏 | 高级模式展开独立调试工具栏，参数预设放入菜单 |
| Opportunity | 鼠标滚动参数面板可能意外改值 | 数字框/选项框过滤滚轮改值，键盘方向键仍能调整 |

主题集中在 `ui/Theme.h`，SVG 位于 `ui/icons/`，由 Launcher 的 Qt Resource 嵌入。主窗口、参数插件和调试窗口共享样式；算法库没有新增界面依赖。

主面板可以从“视图”菜单重新显示，也可以“恢复默认布局”。状态以“就绪、运行中、已暂停、处理完成、处理失败”等文字区分，颜色只是辅助。图层显隐保留勾选形状，结果点大小继续加粗，不单靠颜色表达结果。

## 键盘操作

主视图与调试弹窗中的点云均支持：左键按住拖动旋转、右键按住拖动平移、滚轮缩放。

| 操作 | 快捷键 |
| --- | --- |
| 导入点云 | Ctrl+O |
| 导出选中点云 | Ctrl+Shift+S |
| 适应主视图 | Ctrl+0 |
| 运行 / 停止 | F5 / Shift+F5 |
| 下一步 / 继续 | F10 / F6 |
| 查看选中历史快照 | Enter |
| 切换选中图层显隐 | Space |

参数编辑器提供可访问名称，范围和向量子控件分别命名；控件焦点使用清晰描边。调试窗口保留适应视图、停止、继续与突出显示的下一步，支持 F10/F6/Shift+F5。

复现命令：

```powershell
./scripts/Invoke-Local.ps1 Build
./scripts/Invoke-Local.ps1 Test
./scripts/Invoke-Local.ps1 Smoke -SmokeArguments @('--theme','light')
./scripts/Invoke-Local.ps1 Smoke -SmokeArguments @('--theme','dark','--font-scale','1.25')

```

`--theme` 是本次进程覆盖，不保存偏好；通过“视图”菜单切换才会保存。`--font-scale` 接受 1–2 倍，用于检查放大字体。截图和运行报告由 `--smoke-test` 写入可执行文件所在目录。

### DPI 越界修复（同日后续）

用户实际截图暴露了上一轮验证的缺口：截图捕获的是 QWidget 全部内容，即使窗口超出桌面也能生成完整图片。旧测试的 1440×900 逻辑窗口在本机屏幕上放不下，因此前述图片检查不能证明桌面可用性。

实测原进程 `GetDpiForWindow` 为 144（Windows 150%），旧版 Qt 报告设备像素比为 2；固定最小 1000×620 又超过其 960×504 的可用逻辑区域。修复使用 Qt 的 [缩放取整策略 API](https://wiki.qt.io/New_Features_in_Qt_5.14)，在创建 QApplication 前设置 PassThrough，并让最小尺寸、面板宽度和次要信息适应可用空间。长文件名使用省略和工具提示，避免撑开面板。

新的烟测同时检查窗口框、调试弹窗与运行按钮边界，任一越界即返回失败。覆盖本机原生 150%（可用区域 1280×672，启动 1240×622）、通过进程局部 `QT_SCALE_FACTOR` 模拟的约 125%（1440×756）和 200%（920×454），均完成 3 个检查点并通过边界检查；测试没有修改 Windows 显示设置。长文件名和深色面板也参与了测试。证据位于 `build/dpi-review/`，原有 QtTest 回归继续通过。

`--window-size` 是开发验证的显式覆盖；指定超过桌面的尺寸会被烟测判为失败。日常启动无需此参数。

## 设计稿适配（2026-09-17）

参考 `ui/stitch_qt/screen.png` 和同目录的 HTML，将原有 Qt Widgets 界面调整为深色三栏：顶部品牌与快捷操作、左侧输入和图层、中央悬浮视图提示与导入空状态、右侧算法参数及固定运行按钮。参数项改用上方标签，范围值并排，避免窄侧栏中标签和输入框相互挤压。保留可停靠面板、亮色切换、日志/调试窗口、点云图层和原有算法交互；设计稿中的静态算法名称与示例数值没有硬编码到程序。

Release 构建和框架测试通过。深色默认、亮色和深色 1.25 倍字体的真实 Qt/VTK 烟测均完成 3 个检查点，窗口、调试弹窗和运行按钮都位于屏幕内。更新后的界面已通过 `Invoke-Local.ps1 Install` 安装到 `install/bin`。
