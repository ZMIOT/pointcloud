# 算法参数接入指南

适用范围：当前工程的 C++17、Qt 5、PCL 1.11 插件框架，参数语法版本 1。

本文面向算法开发者，说明如何定义参数、自动生成参数界面，并在算法中读取用户填写的值。内容依据当前 SDK、参数编辑器和插件加载实现。

## 1. 先理解接入流程

```text
parameters.json：描述参数类型、默认值、约束、分组
         ↓ 通过 Qt Resource 嵌入算法 DLL
插件 parameterSchema()：返回参数定义
         ↓ 框架解析、校验并生成参数界面
用户修改参数并点击运行
         ↓ 核心再次校验，冻结本次运行的参数值
算法 execute()：按参数 id 读取，传给自己的 PCL/OpenCV 计算
```

你需要写参数定义和算法计算代码，不需要编写 QWidget。**添加一个配置项只会生成控件，不会自动改变算法行为**；算法必须读取并使用这个参数。

界面标签可以修改，但代码使用的 `id` 应保持稳定。一次运行开始后再修改界面参数，只影响下次运行。

## 2. 支持哪些参数类型

配置类型与 C++ 类型不是一一对应。JSON 使用 `number` 表达数值；本框架用 `type` 区分整数、浮点和复合参数。

| 算法需要的参数 | JSON 中的 type | 默认值例子 | 自动控件 | C++ 读取方式 |
| --- | --- | --- | --- | --- |
| float 单精度浮点 | `double` | `0.02` | 浮点输入框 | `static_cast<float>(p["leaf_size"].toDouble())` |
| double 双精度浮点 | `double` | `0.01` | 浮点输入框 | `p["distance"].toDouble()` |
| int 整数 | `int` | `200` | 整数输入框 | `p["iterations"].toInt()` |
| bool 开关 | `bool` | `true` | 复选框 | `p["enable_downsample"].toBool()` |
| 文本 | `string` | `"处理结果"` | 单行或多行文本框 | `p["name"].toString()` |
| 下拉选项 | `enum` | `"z"` | 下拉框 | 按候选值的类型读取 |
| 数值范围 | `range` | `{"lower":-1,"upper":1}` | 下限、上限输入框 | `toObject()` 后分别读取 |
| 文件路径 | `file` | `""` | 输入框和浏览按钮 | `toString()` |
| 目录路径 | `directory` | `""` | 输入框和浏览按钮 | `toString()` |
| 三维向量 | `vector3` | `[0,0,0]` | X/Y/Z 输入框 | `toArray()` 后读取三个分量 |
| RGBA 颜色 | `color` | `[70,245,140,255]` | 颜色选择器 | `toArray()` 后读取四个整数 |

### float 与 double 的区别

**当前没有 `"type": "float"`。** 这样写会报不支持的类型。两种浮点参数都配置成 `double`，如果 PCL 接口需要 `float`，在算法边界显式转换。

```cpp
const double distance = p["distance"].toDouble();
const float leafSize = static_cast<float>(p["leaf_size"].toDouble());
```

`decimals` 控制允许的小数位数，不表示 C++ 存储类型，也不能消除二进制浮点误差。转换成 float 可能损失精度；用合理的 `min/max` 限制业务范围，避免超出目标类型可表示的范围。当前 `int` 为有符号 32 位整数，没有独立的 int64 类型。

## 3. 参数定义的整体格式

以下示例是一份完整的、包含单个浮点参数的定义文件：

```json
{
  "schemaVersion": 1,
  "algorithmId": "custom.identity",
  "parameterVersion": 1,
  "title": "我的算法参数",
  "groups": [
    {
      "id": "basic",
      "title": "基本参数",
      "parameters": [
        {
          "id": "leaf_size",
          "type": "double",
          "label": "体素尺寸",
          "default": 0.02,
          "min": 0.001,
          "max": 10000,
          "step": 0.001,
          "decimals": 3,
          "unit": "坐标单位",
          "description": "尺寸越大，保留的点越少。"
        }
      ]
    }
  ]
}
```

该单参数示例只演示结构；复制到现有算法前，需要保留该算法代码正在读取的其他参数。

| 字段 | 含义与约定 |
| --- | --- |
| `schemaVersion` | 框架语法版本，当前固定为 1 |
| `algorithmId` | 所属算法 ID，必须与插件声明一致 |
| `parameterVersion` | 算法参数契约版本，正整数，与插件元数据一致 |
| `title` | 定义标题；算法列表名称由插件 descriptor 提供 |
| `groups` | 参数分组数组，按配置顺序显示 |
| 分组 `id/title` | 唯一分组标识、界面分组名称 |
| `parameters` | 当前组内的参数数组 |
| 参数 `id` | 整个算法内唯一，是算法读取参数的键 |
| `type/default` | 必须提供支持的类型及合法默认值 |
| `label/description/unit` | 界面名称、说明和单位提示 |
| `advanced` | 放在分组或参数上，表示仅在高级模式显示 |

文件使用 UTF-8、标准 JSON，不写注释和尾随逗号。布尔值写 `true/false`，数值写数字，不要写成字符串。`unit` **仅用于显示，不自动转换单位**：点云坐标是毫米时，算法使用的长度参数也应采用毫米，或由算法显式换算。

## 4. 常见参数的写法

本节各 JSON 对象放进分组的 `parameters` 数组中，不是独立的完整定义文件。

### 4.1 整数

```json
{"id":"iterations","type":"int","label":"迭代次数","default":200,"min":1,"max":10000,"step":10}
```

`min/max/step` 使用整数，`step` 必须大于零。步长控制按钮增减，**不会要求所有输入都是步长的整数倍**。

### 4.2 浮点数

```json
{"id":"distance","type":"double","label":"距离阈值","default":0.01,"min":0.000001,"max":10000,"step":0.001,"decimals":6}
```

默认值必须在边界内，并满足声明的小数精度；`decimals` 支持 0–15。建议显式填写，避免依赖控件的默认精度。JSON 不支持 NaN、Infinity。

### 4.3 范围值

```json
{"id":"limits","type":"range","valueType":"double","label":"保留范围","default":{"lower":-1.0,"upper":1.0},"min":-1000,"max":1000,"step":0.01,"decimals":3}
```

- `valueType` 必填，只能是 `int` 或 `double`。
- `lower/upper` 是用户实际选择的下限和上限。
- `min/max` 是两个输入框允许填写的边界，不能替代 `lower/upper`。
- 框架检查 `lower <= upper`；算法决定过滤是否包含端点，当前示例使用闭区间。
- 如果需要整数索引范围，改为 `valueType: "int"`，默认值、边界和步长均使用整数。

### 4.4 下拉选项

```json
{
  "id": "axis",
  "type": "enum",
  "label": "过滤方向",
  "default": "z",
  "options": [
    { "value": "x", "label": "X 轴" },
    { "value": "y", "label": "Y 轴" },
    { "value": "z", "label": "Z 轴" }
  ]
}
```

界面显示 `label`，算法收到 `value`。算法读取的是 `"z"`，不是第三项的位置，也不是 `"Z 轴"`。

候选值支持字符串、数值或布尔，必须唯一，默认值必须属于候选集合。建议一个下拉框使用同一种候选值类型；字符串便于以后扩展。若使用数字枚举，算法按 `toInt()` 或 `toDouble()` 读取；数值 `1` 与字符串 `"1"` 不相同。

### 4.5 开关和文本

```json
{"id":"enable_downsample","type":"bool","label":"启用降采样","default":true}
```

```json
{"id":"name","type":"string","label":"结果名称","default":"处理结果","required":true,"maxLength":64}
```

文本可加 `multiline: true` 生成多行编辑器，也可用 `pattern` 指定正则。正则匹配完整字符串；反斜杠需要按 JSON 规则转义，例如数字模式为 `"\\d+"`。

### 4.6 文件、目录、向量和颜色

```json
{"id":"reference_file","type":"file","label":"参考点云","default":"","required":false,"mustExist":true,"filter":"Point cloud (*.pcd *.ply)"}
```

```json
{"id":"output_directory","type":"directory","label":"输出目录","default":"","required":false,"mustExist":true}
```

```json
{"id":"offset","type":"vector3","label":"平移向量","default":[0,0,0],"min":-1000,"max":1000,"step":0.01,"decimals":3}
```

```json
{"id":"result_color","type":"color","label":"结果颜色","default":[70,245,140,255]}
```

路径默认值为空且 `required: false` 时，可以不选文件；填写路径后才检查存在性。`filter` 控制文件选择器的过滤条件，不等于核心校验扩展名或文件内容。向量的数值约束应用于全部三个分量；颜色必须是四个 0–255 整数，最后一个是透明度，255 表示不透明。

## 5. 接入算法插件

建议从 [现有独立插件模板](../examples/algorithm-template/) 开始。以下使用模板已有的 `custom.identity`，并配合 [完整类型示例 JSON](examples/algorithm-parameters.json)。实际项目请使用自己的稳定 ID。

### 第一步：放置参数文件并嵌入资源

把完整示例复制到插件工程，命名为 `parameters.json`。模板的 `parameters.qrc` 内容是：

```xml
<RCC>
  <qresource prefix="/custom.identity">
    <file>parameters.json</file>
  </qresource>
</RCC>
```

### 第二步：让 CMake 编译资源并声明版本

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyAlgorithm LANGUAGES C CXX)
find_package(FrameworkSDK 1 CONFIG REQUIRED)

framework_add_plugin(MyAlgorithm
  TYPE algorithm
  ID custom.identity
  ALGORITHM_ID custom.identity
  VERSION 1.0.0
  PARAMETER_VERSION 1
  SOURCES MyAlgorithm.cpp parameters.qrc)
```

`ID` 是插件 ID，`ALGORITHM_ID` 是算法 ID，概念不同，可以采用不同字符串。这里为了与现有模板一致，使用相同值。算法 ID 在 CMake、JSON 和 descriptor 中必须一致；参数版本在 CMake 与 JSON 中必须一致。

### 第三步：插件返回定义

以下方法放在实现 `fw::IAlgorithmPlugin` 的类中；保留模板已有的插件声明、create/destroy 等方法：

```cpp
#include <QFile>
#include <QJsonDocument>

fw::AlgorithmDescriptor descriptor() const override {
    return {"custom.identity", QStringLiteral("我的算法"),
            "1.0.0", {"x", "y", "z"}};
}

QJsonObject parameterSchema() const override {
    QFile file(":/custom.identity/parameters.json");
    if (!file.open(QIODevice::ReadOnly)) return {};
    return QJsonDocument::fromJson(file.readAll()).object();
}
```

资源前缀不要求等于算法 ID，但必须与读取路径一致。返回空定义或损坏定义时，核心会拒绝加载该算法并记录诊断。

### 第四步：执行函数读取参数

以下片段放在 `execute()` 内，`p` 是该函数接收的 `const fw::ParameterSet&`，对应完整类型示例的参数 ID：

```cpp
const QString name = p["name"].toString();
const bool enabled = p["enable_downsample"].toBool();
const float leafSize = static_cast<float>(p["leaf_size"].toDouble());
const double distance = p["distance"].toDouble();
const int iterations = p["iterations"].toInt();
const QString axis = p["axis"].toString();

const auto limits = p["limits"].toObject();
const double lower = limits["lower"].toDouble();
const double upper = limits["upper"].toDouble();

const auto indices = p["index_limits"].toObject();
const int firstIndex = indices["lower"].toInt();
const int lastIndex = indices["upper"].toInt();

const QString notes = p["notes"].toString();
const QString referenceFile = p["reference_file"].toString();
const QString outputDirectory = p["output_directory"].toString();

const auto offset = p["offset"].toArray();
const double dx = offset[0].toDouble();
const double dy = offset[1].toDouble();
const double dz = offset[2].toDouble();

const auto color = p["result_color"].toArray();
const int red = color[0].toInt();
const int green = color[1].toInt();
const int blue = color[2].toInt();
const int alpha = color[3].toInt();
```

按需包含 `<QJsonArray>`、`<QJsonObject>` 等头文件。这些读取代码本身不执行降采样或过滤，接下来需要把值传给自己的算法。例如当前示例将 `leafSize` 传给 PCL 体素滤波器的 `setLeafSize()`。

框架运行前已做通用校验，但依赖输入点数、单位或多个参数组合的业务约束仍在算法 `validate()` 中检查。参数 ID 拼错时，Qt 的 `toDouble()/toInt()` 可能返回零，不能依赖转换函数发现拼写错误。

### 第五步：编译和发布

使用与宿主一致的 SDK、工具链和依赖，编译 DLL，退出工作台后放入 `plugins/algorithm`，再重新启动。定义已嵌入 DLL 时，不需另发 JSON。不要留下同算法 ID 的旧 DLL 副本。

开发期间可在 DLL 同目录放置 `<DLL文件主名>.parameters.json` 覆盖内嵌定义。例如 `MyAlgorithm.dll` 对应 `MyAlgorithm.parameters.json`。重启后加载，算法 ID 和参数版本仍须匹配。覆盖文件损坏会禁用算法，不会静默退回内嵌定义；发布前移走不需要的覆盖文件。

## 6. 参数联动和高级参数

在体素尺寸参数上加以下字段，勾选降采样时才能编辑：

```json
"enabledWhen": {
  "parameter": "enable_downsample",
  "operator": "eq",
  "value": true
}
```

换成 `visibleWhen` 则控制显示/隐藏。支持 `eq/ne/lt/le/gt/ge`，以及非空的 `all/any` 条件组合，不支持执行脚本。引用的参数必须存在，不能形成循环依赖。

**隐藏或禁用不等于删除参数**：其值仍会传给算法并被校验。因此算法仍应使用 `if (enabled)` 判断是否执行降采样，不能把控件变灰当成算法自动跳过。

在分组或参数上设置 `"advanced": true` 可归入高级模式；它同样不改变值的传递和校验。

## 7. 参数定义与用户预设不是同一份文件

定义文件说明“有哪些参数、怎么展示”；预设文件保存“用户填了什么”。例如：

```json
{
  "algorithmId": "custom.identity",
  "parameterVersion": 1,
  "values": {
    "name": "我的结果",
    "leaf_size": 0.05,
    "axis": "z",
    "limits": { "lower": -0.5, "upper": 2.0 }
  }
}
```

同版本预设缺失项补默认值，未知项提示并忽略，非法值拒绝套用。版本不一致时调用插件 `migrateParameters()`；未提供有效迁移时拒绝旧预设。修改标签不必改参数 ID；改变含义、删除或重命名参数时应升级参数版本，并处理迁移。

## 8. 接入检查和常见错误

1. JSON 能正常解析；算法 ID、参数版本、资源路径正确。
2. 所有参数 ID 在整个算法中唯一，而不只是组内唯一。
3. 每个默认值符合类型、边界、小数精度及枚举候选值。
4. 范围参数有 `valueType`，下限不大于上限。
5. 开关用布尔值，数值不加引号；不把 `float` 当成已支持的配置类型。
6. 算法按 `value` 读取枚举，不按中文标签或下拉序号读取。
7. 算法中的 ID 与 JSON 一一对应；变更参数值能实际改变预期计算行为。
8. 核对点云与长度参数单位；float 转换不会溢出，精度满足算法要求。
9. 检查普通模式、高级模式、联动、预设保存加载和一次实际运行。

错误信息可以在工作台“日志与统计”中查看，面板可从“视图”菜单打开。定义加载失败时算法不会出现在可运行列表中；界面编辑时会显示参数校验问题，运行前核心还会再次检查。
