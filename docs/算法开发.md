# 开发一个算法 DLL

从 `examples/algorithm-template` 复制一个独立工程。只需要 SDK 安装目录以及相同版本的 Qt/PCL/OpenCV 开发依赖，不需要界面源码。

## 插件声明

`framework_add_plugin` 生成供 `Q_PLUGIN_METADATA` 使用的元数据，并链接 `Framework::SDK`：

```cmake
find_package(FrameworkSDK 1 CONFIG REQUIRED)
framework_add_plugin(MyAlgorithm
  TYPE algorithm ID company.my_plugin ALGORITHM_ID company.my_algorithm
  VERSION 1.0.0 PARAMETER_VERSION 1
  SOURCES MyAlgorithm.cpp parameters.qrc)
```

如需额外 PCL 组件，在外部工程自行 `find_package(PCL 1.11 REQUIRED COMPONENTS filters ...)`、链接对应目标；PCL 1.11 Windows 包的 FLANN 头文件可能需显式添加 `${FLANN_INCLUDE_DIR}`。不要覆盖 SDK 的编译器、CRT、配置或 ABI 相关选项。

实现 `fw::IAlgorithmPlugin` 的 descriptor、parameterSchema、create、destroy。工厂方法在工作线程调用，因此不得创建以插件 QObject 为父对象的子对象。插件对象在主线程加载并保留至进程结束。`destroy` 必须在同一个插件中释放实例，且不能抛异常。

## 执行接口

```cpp
QString validate(const fw::AlgorithmInput&, const fw::ParameterSet&) const;
fw::AlgorithmResult execute(const fw::AlgorithmInput&,
                            const fw::ParameterSet&,
                            fw::IExecutionContext&);
```

输入点云只读。通用存储使用 `PCLPointCloud2`，算法可使用 `fw::toCloud<PointT>()` 做局部类型转换。先通过 `requiredFields` 和 `validate()` 校验字段与输入要求；转换不能被误当作保留自定义字段的输出路径。

输出包含命名点云、显示图层、统计以及成功/失败/取消状态。设置每个输出的 `name`、`id`、坐标系和单位。宿主在销毁算法实例前复制最终输出，避免输出引用插件实例的可变缓存。

如果算法涉及较长循环，请周期性检查 `context.isCancelled()`；也可调用 `context.progress(0..100)` 和 `context.log()`。异常由核心转换为失败结果，但内存破坏和系统级异常不保证可恢复。

## 检查点

```cpp
if (context.debug().enabled()) {
    fw::DebugFrame frame;
    frame.stepId = "filter";
    frame.title = QStringLiteral("滤波结果");
    frame.layers = {
        fw::DebugLayer::background(QStringLiteral("输入"), input),
        fw::DebugLayer::result(QStringLiteral("输出"), output)
    };
    frame.metrics = {{"count", double(output.cloud->width * output.cloud->height)}};
    if (context.debug().checkpoint(frame) == fw::DebugAction::Stop)
        return fw::AlgorithmResult::cancelled();
}
```

调试接口从执行线程同步调用，不允许同一运行的多条子线程并发提交检查点。`enabled()` 放在构造 frame 之前，关闭调试时避免准备图层。检查点返回后可以修改算法自己的缓冲区；框架快照已经独立复制。

一个 frame 可含多个点云、图像或几何图层。图像约定为 OpenCV 灰度/BGR/BGRA；显示自动转换为 RGB。几何使用 `GeometryKind` 和 `vertices`：点列表、两点线段、折线、平面有序多边形、包围盒的最小/最大两个角点。结果图层默认高亮，也可修改 `style`。

检查点只上报数据，不使用 QWidget、VTK actor 或 PCLVisualizer。一个步骤在循环中可以反复使用相同 `stepId`，框架通过运行编号和事件序号区分各次结果。

## 发布

退出工作台，将新 DLL 放到 `plugins/algorithm`；参数定义通过 `.qrc` 嵌入，不需要额外复制。替换时移除旧文件，不能仅将旧文件改名仍放在扫描目录中。插件 ID 或算法 ID 冲突时所有冲突副本都会被禁用。

如果插件增加了 SDK 基础依赖以外的动态库，也要随部署包提供，并重新运行依赖检查。不要覆盖工作台现有的不同版本 Qt、PCL 或 VTK DLL。
# 自动诊断接入前置阅读

AI 或人工新增、修改算法前，先阅读 [自动诊断协议](自动诊断协议.md)及[实施计划](自动诊断实施计划.md)。可选诊断档案写在参数 schema 的 `diagnostics`，运行事实写在 `metrics.diagnostics`；用 `fw::Diagnostics` 校验并运行一致性测试。输出目标身份、实测/拟合角色、局部位置与缺测语义需明确，不能把算法自身评分当作正确概率。
