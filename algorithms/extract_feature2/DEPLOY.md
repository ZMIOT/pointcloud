# 安装 ExtractFeature2 算法

退出工作台，把本包的 `plugins/algorithm/ExtractFeature2Algorithm.dll` 复制到工作台同名目录。重新打开 `Launcher.exe`，选择“ExtractFeature2：三面保留与焊缝提取”。1.9.0 默认执行“完整流程：主体保护＋两条焊缝”。高级参数“处理范围”仍可选择仅第一步或旧流程。

完整流程先执行主体与底面保护，再使用受保护的实测点识别左右交线。此分支不再执行旧外壁包络裁剪、离群滤波或体素降采样；`useHullEnvelopeCrop`、`voxelSize`、`outlierMeanK`、`outlierStddev` 及旧包络参数只影响旧流程，三面分析网格仍有效。原始帧号用于截面和输出对应关系；无帧号时使用空间截面。

1.9.0 将参考曲面拟合与原始点清理分开：`hullSurfaceDistance`（默认 0.6）仍用于严格参考曲面拟合；新增 `hullPreservationMargin`（默认 3.0，单位同输入）用于主体有界曲面支持范围内的原始点保留。清理阈值取两者最大值，设为 0 可复现 1.8 的严格清理。保护带不扩大投影支持边界、不把恢复点作为新种子、不生成或投影点，也不放宽焊缝局部面 RMS 验收条件。

未通过严格参考曲面条件、但位于保护带内的原始点记录为 `protectedUncertainPoints`，调试第一步显示为橙色。它们可能包含粗糙焊趾、真实形变或近面干扰，不能把保留数当作正确率。完整流程把这些点交给后续独立的稳健拟合，不再预先按 0.6 的拟合容差切掉它们。

完整流程的剖面采样间距由 `protectedProfileBinSize` 控制（默认 0.6），最小两缝间距由 `protectedMinSeamSeparation` 控制（默认 6）；旧流程仍使用原参数。带帧号输入在每帧的正交平面坐标中拟合，再逆变换回原始 XYZ，避免倾斜截面投影到固定坐标面造成角度压缩。不同帧号之间的大缺口不参与相邻 3–5 帧窗口。局部面搜索使用纵向范围索引加速，范围覆盖所有原有拟合判据，不新增滤点规则。

主体的“最大块”只决定待处理对象，不能再用“最长焊缝段”代替整条焊缝。新流程保留所有至少有三个有效截面的连续焊缝段，分别进行路径优化和局部底面求交，不跨长缺口平滑或连线。短缺口只在两端有支持时按 `maxInterpolatedGapStations` 插补，并在 `quality_flags` 的第 0 位标识；不向首尾弱特征区外推。未输出站位不自动判为输入缺测，定位准确性和完整性仍需人工真值或实测复核。

局部模型从固定参考点拟合，法向分组防止把侧壁和底面平均成一个斜平面；用投影支持边界限制恢复范围。在原始底面法向支持中断的区域，可从原始样本建立候选曲面，但须获得主体周围点的几何接触支持。恢复点不参与继续扩张。搜索半径是分析网格的 18 倍，距离容差仍由 `hullSurfaceDistance` 控制。真实大缺测或强形变不能由此自动证明或修复。

第一步调试检查点中：青色为保留主体，绿色为恢复的原始实测点，红色为剔除点；绿色数量不是准确性分数。完整流程最终只显示受保护主体、黄色左焊缝、绿色右焊缝，不把剔除点作为背景重新显示。三份输出 ID 为 `left_seam`、`right_seam`、`hull_body`。焊缝包含 `segment_id`、`quality_flags`、局部面 RMS、置信度及可用的原始帧号；这些证据不是准确性真值。诊断报告通过显式 `cloudIndex` 关联输出。

输出 `hull_body` 保留原始 XYZ 和附加字段（包括 `frame_index`），不补点、不改坐标。两侧壁和底面允许法向不同，不能因此拆开主体。局部面容差过小可能损失粗糙边缘，较大的网格可能误连邻近干扰。与主体紧密相连且同样具有面支持的干扰仍可能留下；最大连通块不等于已验证船体完整，不对缺测自动补齐。

参数版本 8 可迁移版本 3–7，新增保护余量为 3.0，保留其余参数和旧预设显式选择的处理范围；没有处理范围字段的旧预设仍迁移到仅第一步以保持兼容。使用旧预设时请显式切换到完整流程，或恢复默认参数。旧流程的帧窗口、方向筛选、稳定分箱与 RTS 保留。

要求与本插件一致的 FrameworkSDK、MSVC v142 x64 Release、Qt 5.14.1、PCL 1.11.0、VTK 8.2 和 OpenCV 4.2 构建环境。宿主启动时检查构建标识。

普通 PCD/PLY 输入无需 manifest，默认参数使用毫米数据。原始帧输入需通过源码工程附带的转换器把明确的帧号保存为 PCD frame_index 字段。旧版 frame_seam 参数预设不能应用到本插件。

## 验证范围与历史基线

`build.ps1 Test` 包含旧流程、底面保护、完整焊缝三组测试。完整流程验证已知合成 U 形交线（含逐帧倾斜的弯曲扫描轨迹，世界坐标误差小于 1 mm）、原始底面记录不变、调试/普通输出与诊断一致、参数迁移、取消，以及有/无帧号输入的缺口分段。这些合成真值检查不等同于真实工件定位精度。

1.8.0 历史基线：`2.txt` 原始 3,467,641 点、3,176 帧；主体保留 1,981,634 点、1,915 帧。两侧各输出 1,665 点，帧号 1363–3027，每侧 13 个短插补点；弱局部几何约束分别为左 466、右 511 点。用户后续指出主体清理在底面交界留下长条缺口，此基线不代表合格定位。

1.9.0 第一阶段实测保留 2,014,840 点，比基线额外保留 33,206 个原始点。相同坐标窗口的对照图中原先成片切除的交界长条已恢复原始纹理，不能据此断言所有噪声均已剔除或焊缝准确。新增合成粗糙交界测试验证严格结果为保护结果的子集、实测坐标不变、不填真实输入空洞、独立平行干扰不被拼回，以及可疑保留点的诊断/调试一致性。未提供真实工件人工焊缝真值，定位精度仍待复核。

1.9.0 的 `2.txt` 完整流程已通过主软件隔离试跑和诊断校验，两侧仍各为 1,665 点、13 个短插补点。原始点保留改善不等于交线定位改善：两侧局部跳动仍存在，最大相邻点距离约为左 4.32、右 5.85（输入单位），严格局部几何约束未全部通过的点数分别为 363、573。此版本解决清理过窄造成的长条删点，不宣称焊缝定位已经合格。

主软件集成检查使用 `ExtractFeature2TrialSmoke` 调用 `Runtime::startTrial`；只发出 `trialFinished`，不调用正式 `start`，不创建窗口或向正式数据列表添加结果。宿主目录须使用绝对路径。诊断档案/报告由 `fw::Diagnostics` 校验，试跑结果单独导出到构建目录供对照。
